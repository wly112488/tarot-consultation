# Session Contract — single conversation

本文件由入口 Skill 先读取，所有后续阶段共享；阶段之间无需重复粘贴整个咨询记录。

## Minimum state

持续在**当前会话**的上下文中维护下列信息（不向客户展示技术字段）：

```yaml
session:
  stage: OPENING
  round: 1
  topic: null
  question: null
  confirmed_context: []      # 客户亲述可确认的事实及时间，不要变成对第三人的事实断言
  spread: null                # 类型、牌数、各牌位的顺序与定义
  draw:
    method: null              # READER_DRAW / NUMBER_POSITIONS / CLIENT_CARDS
    randomness_source: null   # TIMESTAMP_SHA256_FY / SIMULATED / CLIENT_PHYSICAL
    shuffle_locked: false     # prepare成功并保存状态后才可通知客户发送数字
    shuffle_version: null     # tarot-sha256-fy-v1
    timestamp_ms: null        # prepare使用的Unix毫秒时间戳
    state_file: null          # 实际工具可读写的本轮私有状态文件路径
    commitment: null          # 洗牌与正逆位摘要，非反操纵证明
    deck_order: null          # 当前轮洗乱后的完整78牌排列；不得从排序索引临时映射
    orientation_by_position: null  # 洗牌时锁定的各位置正逆位
    selected_numbers: []      # 客户所选位置，不含固定牌名映射
    orientation_rule: null
    cards: []                 # 牌位、牌名、正逆位，保持唯一牌
    locked: false
  original_interpretation: null  # 在读取客户反馈前先形成并保留
  feedback: []                # fact / feeling / hypothesis / wish / disagreement
  revisions: []               # 原推断→新推断→依据；不覆盖原始结果
  unresolved: []
  next_action: null
```

这是信息契约，不要求向用户输出 YAML，也不代表 ChatGPT 拥有持久数据库。会话过长、关键信息不可见时，只请求最少的关键信息，不能凭空补全或假称保留。

## Invariants

1. **顺序**：先固定问题、牌阵、牌位与抽牌/正逆位规则。数字抽牌可先引导客户默想并在输入框暂存数字，但必须在通知发送和收到数字之前洗乱并锁定完整78张牌及位置方向；收到数字后只按已锁定的位置取牌。先完成抽牌，再独立初解；后收集反馈并复核。
2. **牌面不可重写**：同轮 78 张完整牌组无放回，牌位与正逆位锁定；数字抽牌不得使用原始牌名索引的顺序作为固定映射，或因客户数字调整牌序；只能新增注明用途的补牌，不能替换原牌。
3. **原始解释不可重写**：初解应在反馈前表达并保留，修订附记录，不得逆向冒充初始预言。
4. **三种证据分层**：传统牌义是解释约定；牌阵推断是可质疑假设；客户亲历的明确事实可纠错，感觉/对第三人的猜测/期待不是已验证的外部事实。
5. **不自证**：冲突无法合理化解时如实承认，不凭“隐藏能量”“延迟兑现”或事后修改时间/对象来维持永远正确。
6. **不预设心意与未来**：可以表达象征性倾向，不能确认他人隐藏感情、疾病、生死、考试录取或投资结果；重大健康/法律/财务决策以现实证据与专业意见为准。
7. **对话连续**：客户说“继续”“不对”“换一个问题”“结束”时按语义路由；禁止把连续轮次当作新客户重新开场。
8. **自然与非强迫**：每轮最多提出一个必要问题，不为延长会话反复补牌；尊重客户不提供隐私和终止咨询的选择。
9. **映射规则只在内部执行**：不主动展示洗牌后的完整牌序、数字到牌名的对应表；客户追问映射规则时仅说明数字是洗乱后的牌堆位置。客户发送数字且牌序已锁定后直接揭示牌面。抽牌完成后可按要求提供真实存在的核验记录。
10. **洗牌不得伪造**：数字抽牌执行 `skills/draw/scripts/tarot_shuffle.py prepare` 并保存状态文件成功才称洗牌已完成；这是**时间戳种子的确定性伪随机**，不等于强随机性或可证明公平。工具或持久状态不可用时，须说明限制，不能在收数后倒造先前状态。
11. **复现与补牌**：`prepare` 先于客户发送数字，`reveal` 必须引用原状态文件；同轮补牌拒绝重复位置，新轮次必须创建新的状态文件；所有结果可由版本和时间戳再计算验证。

12. **自由选号不诱导**：牌阵固定后可先引导客户专注原问题、在输入框填写所需数量的 1–78 不重复数字但暂不发送；`prepare` 成功后才通知发送。不得提供示例号码、建议数字、预填组合或其他暗示特定数字的文案。

## Decision boundary

- `CLIENT_FACT`：客户描述的明确发生事件（例“我们已经分手”）；纠正错误的当下事实假设，仍避免核实不到的外推。
- `FEELING`：客户自身的感受；作为主观体验尊重，不等于他人心理事实。
- `HYPOTHESIS`：客户推测他人想法、动机或未来；保留为推测。
- `WISH`：客户希望或害怕的结果；不使牌义倾斜。
- `DISAGREEMENT`：客户否定解读；核查牌位/推断/背景，只在有牌义依据时另作解释。
