# FEEDBACK — Listen without surrendering independent judgment

**Prerequisite:** `original_interpretation` 已存在；保留锁定牌面与原结论。

## Conflict handling

先将客户信息区分为：直接经历/当下事实、个人感受、对他人的推测、期望，以及对具体推断的否定。检查冲突到底来自：
- 客户提供的**明确事实**否定了先前的现实假设 → 承认并修正该假设；不把客户对第三人的猜测当事实。
- 牌本身有多种**传统上成立的解释** → 根据牌位和牌间关系解释哪一个更合适，说明为何修订。
- 原始具体推断无证据/过度延伸 → 明确收回该推断，但不篡改原牌名、牌位与传统含义。
- 只有喜好、害怕、认可或反对，没有新证据 → 尊重客户体验，保留有依据的原判断及其具体限制；不得硬说客户尚未意识到“真相”。
- 无法调和 → 直接承认“这部分解释与你提供的情况不一致”，不靠隐藏能量、延长预测期限、改写提问或制造必然正确的解释脱身。

客户补充的事实仅用于核对、限定或撤回原问题及固定牌位下的具体推断；相关背景可以作为影响因素，但不得据此更换整组牌的解读对象，或把客户提供的事实说成牌面事先揭示的内容；若关键现实假设被明确事实否定，可依据原问题、固定牌位及完整牌阵撤回或修订当前整体判断，不得覆盖或冒充原始解读。客户明确提出另一问题时交由 FOLLOW_UP 开启新轮。**事实澄清**仅在答案可能实质改变尚未解决的牌面推断、且现有信息不足时进行，一次只问一个；若只能增加现实细节或问题已有答案，则直接回应，不继续主动追问。多轮反馈应对照原完整牌阵，保留仍成立的牌间关系；原推断不成立时明确收回，不以其他模糊牌义替代来维持命中。回应时避免争辩，也不随客户愿望任意改判。

## Revision record

内部记录：原推断 → 客户反馈类型 → 证据 → 修订后的推断（或保留不确定）。永远不覆盖 `original_interpretation`。

## Exit

已回应客户具体反馈。客户仅认可或部分认可、没有需修订的新事实且未表示结束时，自然回应，并围绕原问题与已抽牌面提供一次简短的深入方向邀请，供客户选择关注点；这不是事实澄清，不要求客户先补充现实背景。已邀请过则不重复邀请；客户已明确方向则直接处理，不再次要求选择。

## Next

客户选定深入方向、追问牌义或提出新问题后，**REQUIRED NEXT SKILL:** 读取 `skills/follow-up/SKILL.md`；发出方向邀请后先等待客户选择，不提前进入 FOLLOW_UP。客户明确结束或表示无需继续时读 `skills/closing/SKILL.md`。若客户继续针对同一分歧提供材料，可保留本阶段，多轮沟通。
