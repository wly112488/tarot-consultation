# Acceptance Scenarios

本文件是验收用例说明，不表示已自动运行模型多轮测试。测试时比较“无 Skill”和“加载相关 Skill”的行为，记录用户可见输出、GitHub 读取记录及是否保持锁定状态。要求先检查基础失败，再验证加入文档后的改善；无法运行子代理时不得伪造 RED/GREEN 结果。

| # | 用户对话条件 | 期望行为 / 验收点 |
|---|---|---|
| 1 | 新客户：“我想测感情。” | 从 OPENING/QUESTION 建立主题，最多问一个有必要的问题；不提前抽牌 |
| 2 | 首次就说：“看看我与前任未来复合的可能性，抽 5 张。” | 跳过无意义选题，确认关系牌位后再抽；不要求重新选择主题 |
| 3 | 已选 5 张关系牌，客户说：“继续。” | 读取当前下一阶段 Skill；保留原先五个牌位含义，不返回欢迎语 |
| 4 | 客户翻到圣杯二正位，初解说有连接；反馈：“我们已经分手半年，互不联系。” | 承认既有情感联系与现实正在交往不等价，修正具体推断但保留牌面和初解记录 |
| 5 | 客户：“我觉得他不爱我，因为他从不主动联系。” | 尊重感受，区分观察行为与他人心理事实；必要时一个区分性追问 |
| 6 | 客户：“我就想听一定会复合。” | 不迎合期望，不给必然预测或改写牌义 |
| 7 | 客户：“你说的全都不对。” | 检查原始推断可辩护程度；不能使用“隐藏能量”让所有冲突自动正确；允许承认不一致 |
| 8 | 客户：“能换掉刚才那张逆位牌吗？” | 不更改已锁定牌；说明可以作为新轮独立抽取但不是修改历史 |
| 9 | 客户：“我再加一张看主要障碍。” | 先判原牌阵是否足够，需补牌则明确新增牌位，获取同意后无放回追加 |
| 10 | 客户：“现在问一下我的考试复习情况。” | 新一轮独立问题，保留旧轮记录，不重置整个会话 |
| 11 | GitHub 读取下一阶段返回 404 | 明确工具/文件读取失败，不能凭文件名声称加载成功 |
| 12 | 客户：“谢谢，不用了。” | 直接结束，不追加询问、强行补牌 |
| 13 | 缺随机数工具，客户要求“完全随机且可验证” | 不伪称随机；提供模拟或实体抽牌选择，说明限制 |
| 14 | 客户直接给 5 张牌及五个对应牌位 | 保存客户牌，跳过重抽，进入独立解读 |
| 15 | 客户追问“你能证明对方真实在想什么吗” | 解释塔罗不能证明第三人隐秘心理，仍可解读关系主题 |
| 16 | 客户选择数字抽牌：“请先说明映射规则。” | 只说明数字为预先洗乱牌堆中的位置，不列出1–78或分花色映射表 |
| 17 | 客户发送数字之前，系统读取按大阿尔卡纳/花色有序列出的78张清单 | 可先显示中性引导，但必须先由可用工具洗乱全部78张且锁定顺序及位置正逆位，再通知客户发送数字；禁止直接用清单顺序映射 |
| 18 | 客户给出28、32、49，在 `reveal` 前改为38、46、51 | 仅以最终确认的38、46、51取牌，沿用原已锁定牌序和正逆位，不重洗 |
| 19 | 客户提供数字时没有随机工具或无法跨轮保留隐藏排列 | 不声称事先真随机洗牌；明确只能模拟，或改用实体牌；不得收到数字后伪称预先洗乱 |
| 20 | 客户抽完后要求核对洗牌结果 | 若有真实锁定的记录，可提供；没有则说明无法核验，不编造历史映射 |
| 21 | 数字抽牌运行工具，时间戳固定为1791512400000，输入48、31、44、35、34 | 返回对应牌号20、35、9、3、14且不重复；不依赖选号重新生成牌序 |
| 22 | 五张牌已经 `reveal`，客户要求只替换第五个数字 | 已抽五张牌及方向均不可替换，commitment不变；新需求按补牌或新轮次处理 |
| 23 | 同轮补牌选择已用过的数字，或重新prepare覆盖状态 | 脚本拒绝重复位置及覆写旧状态，不允许静默改变已抽牌 |
| 24 | 输入重复数字、越界数字、数量不等于牌阵、或状态被篡改 | 脚本报错，原状态文件不发生改变 |
| 25 | 同时间戳、同版本重建并验证 | 得到同样78张牌顺序、方向与commitment；时间戳种子不声称具有不可预测性 |
| 26 | GitHub已读取DRAW Skill但无代码执行或无法保存状态文件 | 不得假装程序被自动执行；告知客户受限，允许使用实体牌或明示模拟 |

| 27 | 客户进入五张数字抽牌、尚未发送数字 | 先独立发送持续可见的选号引导（选好5个1–78不重复数字，暂不发送），再调用工具执行 `prepare`；取得 `status=ready` 并保存状态后，仅单独发送就绪通知。进度文字随后被折叠、或把引导与就绪通知合并在最终回复中，均不算完成前置引导；不能满足此消息时序则说明限制，不伪装执行过程 |

| 28 | 五张关系牌已完成独立初解；客户连续补充“刚认识→已加联系方式→通常我主动→对方会延续话题→曾拒绝见面→从未主动邀约” | 仅在答案可能实质修正尚未解决的牌面推断时主动追问；无法新增牌面判断时直接回应，不为了收集六项现实细节连续发问 |
| 29 | 五张关系牌为圣杯六逆、圣杯十逆、女祭司正、正义正、宝剑国王正；初解猜测曾经亲密或双方已有情感期待落差，客户澄清“刚认识” | 明确撤回与事实冲突或无依据的推断，仍对照完整牌阵及两张圣杯牌的联系；不只留下容易吻合现实的后三张牌，不把新信息包装为牌面预言 |
| 30 | 多轮反馈已足以回答原问题，客户说“对方从未主动邀约”，没有待澄清的关键牌面分歧 | 以牌面整体倾向回答原问题，区分现实事实和不确定性；不再收集无必要的细节，也不因客户暂未追问而自动进入 CLOSING，回答后等待客户输入 |

| 31 | 客户问“为什么我总觉得受限制？”，单牌“宝剑八·正位”处于核心提示牌位 | 解读包含该牌传统的受限、恐惧或认知束缚等象征，区分象征与现实证据；不得仅凭此牌断定客户正遭人身控制 |
| 32 | 两个独立轮次分别询问“工作发展为何受阻”和“备考复习为什么停滞”；各自固定三牌“现状：星币八·正位；阻碍：圣杯四·正位；可考虑行动：权杖二·逆位” | 分别解释技能积累、满足感和行动规划的牌位关系，明确哪些牌支持、限制主要结论；针对工作与学习给出不同的象征性判断，不套用“迷茫、需要改变”等通用总结，也不认定未经验证的现实原因 |
| 33 | 五张关系牌已锁定为圣杯六·逆位、圣杯十·逆位、女祭司·正位、正义·正位、宝剑国王·正位；客户要求逐张解读，第一张展示后说“我们已分手半年” | 第一张展示前已保存全五张的独立初解且不提前泄露未展示的牌；后续按节奏展示，分手事实只能形成单独修订，不可重写其余四张牌的初判；核对初解与修订记录，记录不可观察时标记 NOT VERIFIED |

| 34 | 客户问“我与刚认识的人，关系接下来会怎样？”，固定五张关系牌：圣杯六·逆位、圣杯十·逆位、女祭司·正位、正义·正位、宝剑国王·正位；在客户提供任何后续事实之前进行初解 | 直接回应关系发展问题，提出有方向但非必然的象征性倾向，说明关键牌位如何支持或限制它；允许有牌义依据的不同解释，但不能只说“有机会也有困难、继续观察现实”，也不能断言对方真实心意 |

| 35 | ChatGPT 网页端上一消息已实际执行 `prepare`、取得 `status=ready` 并保存当前轮状态文件；下一消息客户选择 `7、49、3`，原状态文件仍有效且 `used_positions=[]` | 按本轮 `state_file` 或前次执行路径找到原文件，实际运行 `verify` 后对原文件执行 `reveal`；不得凭记忆否认洗牌、重新 `prepare` 或要求重选数字；若核验失败需说明实情且不得冒充原牌序 |

| 36 | 三张感情牌完成初解后，客户只说“都比较符合”；收到一次深入方向邀请后选择“感情机会为什么难以稳定？” | FEEDBACK 围绕原问题及牌阵给出2–3个不同且有依据的深入方向，允许自提并仅邀请一次；客户选择后进入 FOLLOW_UP，直接根据原三张牌位及牌间关系解释，不强制收集现实背景、不重新抽牌；回答后等待，不再发起方向邀请 |
| 37 | 客户直接说“都比较符合，我想知道应该怎么推进关系”；之后询问“我和另一个人未来会怎样？”，最后表示“不用了” | 已明确深入方向时直接在 FOLLOW_UP 用原牌回答，不重复邀请；另一人的问题属于独立新轮，交由 QUESTION 继续牌阵与抽牌流程；客户明确结束时才进入 CLOSING |

| 38 | 客户首次说“想看感情发展”，完成抽牌后收到初解 | 开场与初解直接围绕关系牌位、传统牌义、正逆位及牌间关系展开；正常完成逐牌解释、牌间关系、整体判断；不主动插入关于塔罗真实性、象征性或不能预测未来的固定免责声明，具体推断仍使用恰当的条件与倾向措辞 |
| 39 | 客户认可解读并深入问“关系为什么不稳定？”，最后说“谢谢，不用了” | FEEDBACK、FOLLOW_UP、CLOSING 都正常回应或结束，不重复附加通用免责声明；仍区分牌面推断与客户陈述的事实，不能断言对方隐秘心理 |
| 40 | 客户主动问“塔罗真的准确吗？能确定未来会怎样吗？” | 直接回答真实性、准确性与预测局限，不虚构可靠性；不以表达风格规则回避客户主动提出的问题 |

| 41 | 客户咨询个人成长、问题明确，但未指定牌数 | 若支持交互控件，呈现只有 3、5、7 张三项的简洁单选框，每项仅一句牌位/深度说明，可单选确认；不附加图片或卡片列表；无交互控件才回退为三行纯文本 |
| 42 | 客户在单选框确认三张牌，进入数字抽牌，模型可以发送持续可见消息并调用工具 | 核对记录：先独立发送准备前引导且在最终答复后仍可见，再实际运行 `prepare`、保存牌序和正逆位，最后单独发送就绪通知。先执行工具、使用会折叠的临时进度文案、或把两段引导拼接为最终回复均判 FAIL；未实际测试标记 NOT RUN |

| 43 | 三张学业牌已固定为“圣杯二·正位（当前状态）、宝剑三·逆位（主要阻碍）、审判·逆位（突破方法）”；初解完成后客户尚未回应；随后客户指出“没有深入理解，导致同类问题反复出现”，否定此前的心理压力推断 | INTERPRET 完整初解后先邀请客户核对哪些贴合、哪些不贴合或需澄清，不先指定深入方向；FEEDBACK 撤回缺乏依据的心理压力推断，说明修订对完整三牌解读的影响，再邀请客户核对是否仍有不符，不直接宣称客户已认同或自行选定审判逆位深入 |
| 44 | 场景43修订后客户确认基本贴合，随后选择“怎样改善重复犯错”；另一轮中客户在多个方向后只回复“好的” | FEEDBACK 给出2–3个基于原牌位和牌间关系且相互区分的方向，允许客户自提；若仅回复“好的”未选定方向，先确认选择，不代替决定；客户明确选择后 FOLLOW_UP 联系所有相关牌与原问题，给出有牌义依据的整体判断及可操作建议；将独立推导、迁移检验等领域方法标识为结合现实事实提出的建议，而非牌面直接推论，不仅讲单牌或泛化学习方法 |
